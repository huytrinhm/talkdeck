# Anonymous visitor BYOK — P0 integration

App settings → Connections owns Your API key across projects. No ChatGPT login is required. The actual HTTP adapter is in `ConnectionsClient`; service readiness comes from the host capability endpoint, not a local flag or a saved key. Missing resources hide secret entry and keep the unavailable state truthful.

The actual flow is **Save for session → Not verified → explicit Check key → verified or controlled error**. Save acknowledges encrypted visitor storage only. Check key calls the host-owned verification endpoint, which makes a bounded server-only models-list request. It verifies credential/model-list access, not inference, model access, credits, GPT-Live or coach availability. Main tests mock this entire provider operation and never submit a real key.

The form masks/reveals only its transient draft; submit/cancel/close/tab change clears it. No key is returned by status, stored in controller snapshots, project data, source, URLs, localStorage, reports or logs. The server keeps a one-hour sealed HttpOnly key cookie, bound to an anonymous visitor and a random revocation/version marker. Remove/replace invalidate older cookies through the host marker; keys themselves are never in R2. Main must not invent or activate that storage/security configuration.

All writes use the agreed same-origin visitor/CSRF contract in [connections-wire-v1.md](connections-wire-v1.md). Fetch and response bodies have a20second client deadline; provider verification has a separate10second server deadline. A timed-out/uncertain mutation is not reported successful and is never automatically retried. The controller locks further key mutations until an explicit status check reconciles the authoritative state. Credential expiry does not cancel or unlock a still-pending replacement; its real response can establish a newer session.

The frontend renders only configured/validation/expiry facts and safe error codes. A key can be saved but unverified, rejected, unavailable to model listing, rate-limited or affected by an unknown operation outcome. Removal clears this session's saved credential; provider-wide revocation is a separate OpenAI action.

Current code/tests implement the client; host reports13 mocked service tests. Runtime R2/master-secret activation still awaits the parent's bundled approval. No database, shared provider key, external relay, real key test, provider/inference call, new storage binding or independent deployment was performed by main. Real cookie/session security, visitor isolation and provider behavior belong to hosted verification; frontend mocks do not certify them. Immutable b187 remains preserved while this functional batch develops.
