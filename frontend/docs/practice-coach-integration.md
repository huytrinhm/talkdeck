# Practice coach boundary

The approved companion is practice-only and retains the existing slide, notes and transcript layout. Normal rehearsal never sends to the coach. `PracticeCoachController` is an internal TypeScript boundary; its event names are not a GPT-Live network protocol. The default port is unavailable. No endpoint, raw API event mapping, microphone, audio player, key handling or generated feedback is implemented here.

Configure a genuine `CoachPort` at the composition root before entering Practice. A port advertises text/audio input and voice output separately. `open()` must open with capture and playback off. Only a consented question or explicit Start coach microphone can begin input. Context contains the current slide reference/title and this rehearsal’s captured transcript; it is read at the authorized action, never sent by ordinary navigation. Typed questions have equal access. Spoken replies require separate explicit opt-in and an exact readable reply.

`stopInput`, input mute, output mute, `stopSpeaking` and `close` must synchronously stop the relevant local capture/playback/queued media. The adapter owns session history reconciliation for heard versus unheard audio. `Stop speaking` and output-off do not cancel a delegated service task. No task-cancel control or automatic slide edit exists. A close releases media/session resources; it does not promise that a remote task has been cancelled.

Input, playback and task state are separate. Capture is displayed only after a service input event. A reply text event must precede speaking playback. Pending connection intent is invalidated by input/consent withdrawal, Resume, a new turn, failure or disposal; output-off while connecting is retained. This port has no request correlation contract, so the frontend serializes questions while a service task is running. The serving adapter must honor the same single-task boundary and deliver ordered acknowledgements for its bounded turn. Do not infer supersession/cancellation from a new utterance or transplant older Realtime event names into GPT-Live.

Pause & ask pauses rehearsal input/time first. Resume is explicit and turns coach input/output off. Blur/background pauses input/output and never silently resumes. Route exit or Finish invalidates late events and closes resources. Finish hands only received scoped feedback and the user’s own notes to a bounded, in-memory history keyed by rehearsal ID. Pending/incomplete feedback remains labelled incomplete. A reload discards this optional history; it is not a production persistence contract. Existing slide proposals still require Approve/Reject.

Official service integration reference: [Managing GPT-Live sessions](https://developers.openai.com/api/docs/guides/live-conversations). The owner must agree authentication, per-user session creation, capability checks, timing/acknowledgements, playback interruption and cancellation semantics before enabling this port. An available personal key does not prove any of those capabilities.
