# Recorded provider boundary

`createRecordedModels(client, recorder, configuration)` in `src/headless/models.ts` binds the actual OpenAI SDK and existing orchestration model/decision adapters to one shared budget. It returns `model`, `decider`, `slowDecider`, `budget.snapshot()`, `budget.remaining()`, exact `records()`, per-role `statistics()`, and `replayCassette()`.

Configuration preserves explicit model IDs. Defaults elsewhere remain Fast `gpt-6-luna` with no reasoning, Slow `gpt-6-sol` with medium reasoning, and specialists `gpt-6-sol` with low reasoning. Every Responses request specifies `service_tier: "fast"`, including specialists. The requested and returned tier are recorded separately; a requested tier is not a claim that the provider served it. OpenAI documents Fast mode for Responses and the selected reasoning efforts for Sol: [Fast mode](https://developers.openai.com/api/docs/guides/fast-mode), [GPT-6 Sol](https://developers.openai.com/api/docs/models/gpt-6-sol).

The Decisions endpoint supports only `gpt-6-luna`; its current [create schema](https://developers.openai.com/api/reference/resources/decisions/methods/create) exposes neither `service_tier` nor `max_output_tokens`. Both speech dispatch and Slow eligibility use the real endpoint with no invented tier field or header. `DECISIONS_TIER_POLICY` describes this exception for run configuration records. No model substitution or endpoint fallback occurs.

`ModelInput.instructions` replaces the legacy role instruction completely when supplied. The JSX backend owns those instructions. Empty canonical screenshot buffers are omitted from Slow eligibility input; only explicitly supplied nonempty images become image parts. This provider boundary does not attach screenshots itself.

The default limits are 200 provider requests, two million input tokens, 100,000 output tokens and 8,000 output tokens per Responses request. All are configurable finite positive integers. A single budget covers concurrent Fast, Slow, specialist, speech Decision and Slow Decision calls. Before transport it reserves request UTF-8 byte length plus 1,024 input tokens, plus 65,536 for each explicit embedded image, and the maximum output tokens. This deliberately conservative local reservation is not an authoritative tokenizer: actual provider usage is recorded and releases excess reservation. If usage exceeds a reservation, accounting fails and further requests are blocked. Aborted or failed calls without usage retain the whole reservation and remain visible as unknown usage. Decisions reserve the same local output allowance because a response may report output usage; no unsupported output-limit argument is sent. That allowance is not a provider-enforced Decisions cap: a provider report above it triggers an accounting failure, and the finite shared call limit remains the independent request bound. `snapshot()` separates observed usage from conservatively charged usage.

SDK retries are disabled at both client and call level. A caller-triggered attempt is another recorded and budgeted call. Records retain endpoint, role, agent, exact request/response JSON, provider request ID, status, timing, usage, requested/returned tier, reservations and abort/error outcome. Credentials and headers are never serialized. Authentication error bodies are replaced with a status-only marker because provider authentication messages may echo fragments of a key. Other successful responses remain literal. The environment-only client reads process variables and never opens `.env`.

`createReplayModels(recorder, configuration, cassette)` uses the same SDK serialization and orchestration adapters, with a transport that matches exact request bodies, endpoint, role and agent. It reproduces recorded latency and responses. Context mismatches, exhaustion and unconsumed records fail; no live transport exists. Fixture/source/prompt/dependency compatibility must additionally be checked by the run harness before constructing this provider replay. This transport is only one part of full actor replay and is not evidence that an end-to-end actor replay has passed.

Offline verification covers exact serialization, all role settings, Decisions policy, replaced JSX instructions, absence of implicit images, concurrent call caps, input/output reservations, unknown usage after abort, authentication redaction, no automatic retries, strict Responses/Decisions replay and the real artifact recorder boundary. No paid request is required by these tests.
