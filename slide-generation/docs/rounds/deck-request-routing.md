# Explicit deck request routing

The canonical Fast prompt assigns cross-slide, theme and library work to Slow. Before this fix, Fast had only `finish` among scheduler lifecycle tools, while idle Slow refinement required a Fast publication. An explicit structural request could therefore have no path to its authorized actor when Fast had nothing local to publish.

Canonical Fast now has `request_deck_edit({ scope, utteranceId })`. It forwards a complete original user input to Slow as an existing `edit_comment` task. This is explicit requested work, so it bypasses autonomous refinement eligibility and needs no prior Fast publication. The target remains the original working slide. Fast's actual source-edit permissions are unchanged.

The measured edit-heavy candidate tried to concatenate eight utterances into the previous `sourceQuote` argument, which correctly refused that request. The interface now asks Fast to copy one Prompt `utteranceId` from `notes.transcript` or `read_speaker_notes`. The runtime resolves that ID to the complete durably received original input, including every qualifier. Model-supplied quotes and task text are rejected by the strict schema. This changes selection usability, not delegation policy.

The selected input must belong to the working slide, have arrived by the current inference's speech revision, and still be present in that snapshot. Corrected-away inputs are refused even when replacement text is identical. A later input with identical words cannot pass an earlier inference's identity check. Slow is told to verify the explicit request and perform only its requested scope. This is provenance enforcement; no lexical rule claims to prove semantic intent. Identical IDs from the same slide/speech revision queue once. The request event retains both `utteranceId` and the exact full `sourceQuote` for audit.

Real engine/Chromium tests verify a requested theme edit through Slow with zero Fast publications and zero refinement Decision calls, exact raw-note retention, deduplication, and unchanged Fast edit restrictions. Negative controls cover missing IDs, wrong-slide IDs, inputs arriving during inference, corrected-away IDs, attempted qualifier-dropping quote overrides, additional task fields, legacy mode and Slow tool exposure. Existing scheduler/refinement tests remain passing. No paid model calls were used, so a live effectiveness or latency improvement is not established by these tests.

The bounded recorded-event actor replayer explicitly refuses traces using this new delegation tool until generated task identities are qualified. Transaction replay remains separate. Previously recorded actor requests also differ after adding a tool definition; replay must not silently ignore that contract change.
