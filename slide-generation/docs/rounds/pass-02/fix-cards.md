## Card 1 — preserve canonical error identity in model-facing tool results

**Recorded problem.** Numbers-business candidate refuses two edits at 19,537.259 ms and 35,494.880 ms with `unknown_snapshot`: the supplied handles were issued for Deck `n1`, but the edits target Slide `n10` or `n23`. The model-facing result contains only `Read this node before editing`. Style-switch baseline shows the same mismatch at 22,982.250 ms for Theme `n3` and at 94,562.480 ms for Slide `n10`. Numbers baseline also has six `stale_anchor` refusals, while style candidate has a stale insertion refusal after another actor has already inserted the requested subtitle. The exact structured codes are available in recorded canonical operations, but the inference history loses them.

**Current path.** [SourceError](../../../src/contracts.ts) carries `code`, message, optional `nodeId`, and optional span. [SnapshotStore.stageDetailed](../../../src/hashline.ts) binds each handle to its issued node and checks complete insertion boundaries. [ToolRegistry.invoke](../../../src/tools.ts) and [JsxBackend.invoke](../../../src/host/jsx-backend.ts) record an error code and rethrow. The canonical branch of [SlideRuntime.run](../../../src/orchestration/runtime.ts) catches that error and replaces it with `{error: errorMessage(e)}` before adding the `function_call_output` to actor history and logging `tool_result`. This final conversion discards the structured code and node identity.

**Smallest proposed change.** At that canonical tool-result boundary, retain the existing human-readable `error` string and add the original `SourceError.code` and optional `nodeId` as explicit fields. Use one bounded serializer for the inference-history output and the matching recorded tool result so they cannot disagree. Preserve existing noncanonical behavior and useful generic errors; do not invent a node identity when the thrown error has none. Do not expose stack traces, credentials, unrelated source, or arbitrary exception properties. The diagnostic envelope must leave accepted tool results unchanged.

This does not authorize editing a child with a parent snapshot, guessing new hashes, or silently remapping the model's handle. `unknown_snapshot`, `stale_anchor`, `ambiguous_anchor`, `scope_escape`, `role`, `control_boundary`, and `validation_unavailable` remain distinct refusals. Existing detailed validation messages in [SlideEngine.transact](../../../src/engine.ts) must survive serialization as well.

**Acceptance and replay evidence required.**

- Extend [canonical backend integration](../../../test/jsx-backend.integration.test.ts) and [actor runtime tests](../../../test/orchestration/runtime.test.ts) with an actual thrown `SourceError`. Assert the next fake-model request contains the preserved code/node/message and the recorder contains the identical literal tool output. Test a code with a node, a code without one, a generic error, and a successful tool call.
- Exercise a genuine Deck-handle/Slide-target mismatch and an insertion-boundary change. Both must still refuse with unchanged source, versions, and history; their model-facing codes must differ appropriately. Do not test only a hand-constructed serializer object.
- Replay the recorded numbers/style transactions into new artifact directories with exact original arguments, snapshot-scope validation/remapping, literal outcomes, and source hashes. Existing errors must keep their original semantic codes; do not rewrite recordings to match the new envelope. The new model-visible fields are an intentional actor-input difference and must be reported if exact actor replay stops there.
- Keep bounded actor-replay limitations explicit: numbers recordings include screenshot/message paths outside the currently supported actor fixture coverage. Passing canonical transaction replay is not a claim that the scheduler/provider conversation replayed. Add focused deterministic actor coverage for the new envelope, then run a fresh paired live measurement if claiming improved recovery behavior.

**Separate context-usability issue.** The recorded root-snapshot misuse is not an engine hash defect. A Deck read contains nested slide text, but its handle and line numbers still belong to the Deck. Investigate how the prompt/tool description and repeated deck-versus-working-slide context communicate that scope. A later diagnostic may name the issued and requested scopes when known, with its own contract/test. Keep such context changes separate from this minimal error-preservation patch and from the pending routing decision.

## Card 2 — retain measured geometry when glyph-contrast coverage is unavailable

**Recorded problem.** Numbers-business baseline refuses two overview candidates at 20,031.342 ms and 25,264.454 ms. The recorded failures identify `No native glyph coverage could be measured for t22:text:0` and `t26:text:0`. Both proposals stack a title, three large Stats, and two body paragraphs. Completely clipped or off-canvas text is a plausible explanation, but it has not been reproduced. Do not call clipping the established root cause until the exact candidates have been reconstructed and inspected.

**Current path.** [measurePage](../../../src/browser/measure.ts) first collects native text rectangles, effective typography, bounds, and node identities. It later captures the background and glyph mask for contrast sampling. A text run with no mask coverage throws, despite the nearby comment suggesting geometry findings remain available. [BrowserValidationPipeline.inspect](../../../src/browser/pipeline.ts) calls [evaluateMeasurement](../../../src/browser/policy.ts) only after `measurePage` returns, so that throw discards the current slide's already collected geometry. `checkSlides` can retain earlier slides' completed findings, but the failing slide becomes a generic unavailable finding. The combined policy function also throws on an empty background sample instead of representing that stage's unavailability.

**Smallest proposed change.** Separate trustworthy geometry/typography findings from the availability of subsequent contrast and shape stages. Retain the actual immutable measurement and findings already obtained for the failing slide; identify each unavailable text sample with its actual slide, authored node, and text-run subject. Continue to report measured contrast for runs whose samples are available, where this can be done safely. Preserve Pending identities and earlier completed slide evidence. Return explicit stage/sample availability, not a fabricated contrast value or an implied completed check.

A missing required contrast or shape measurement must keep the overall report `complete: false`. Add a targeted `validation-unavailable` finding alongside actual overflow/size/overlap findings. [SlideEngine.transact](../../../src/engine.ts) must continue refusing when either baseline or candidate validation is incomplete; [ready](../../../src/validation.ts) must remain false. If geometry itself was never collected, report it unavailable rather than inferring bounds from the source. This patch must not skip visible glyphs, lower APCA/font thresholds, suppress geometry, accept invisible content, or treat transient viewer animation as final layout.

**Acceptance and replay evidence required.**

- First reconstruct both exact refused baseline candidates from their original read snapshots and edit arguments using the real stager, candidate preparation, expansion, normalization, and versioning. Preserve full source, hashes, raw reports, rendered bounds, mask diagnostics, and explicit reproduction status in a new artifact directory. Distinguish a known recorded refusal from the independently observed underlying cause.
- Extend [browser integration](../../../test/browser.integration.test.ts) with real Chromium controls: a fully off-canvas/clipped text run, an in-canvas low-contrast run, and a mixed slide with readable text plus an unavailable run. Require retained measured overflow where present, targeted unavailable diagnostics, and no passing contrast claim for missing coverage. Low-contrast visible glyphs must still produce their real contrast failure rather than become silently exempt.
- Extend [browser policy tests](../../../test/browser-policy.test.ts) for partial stage data and preserve the existing overflow, overlap, Stat-wrap, typography-floor, and solid-shape checks. Verify temporary mask styles are cleaned up on success and failure. A failed later stage must not invalidate already measured facts or certify unmeasured stages.
- Extend [engine refusal tests](../../../test/engine.test.ts) and transaction integration coverage: partial reports must refuse atomically, expose useful available findings, and preserve source, assigned IDs, versions, and history. Genuine browser launch/crash/timeout failures must remain incomplete without fabricated geometry.
- Replay the original recorded transactions without new model calls, preserving refusal outcomes and source identity. Extra findings are a deliberate diagnostic-contract difference; report that difference explicitly rather than altering the old recordings or calling strict actor replay unchanged. Re-run the existing renderer/marker/primitive acceptance corpus after implementation. Version changed measurement policy/evidence where necessary, and use the same evaluator/checker conditions for any subsequent comparison.
