# Recorded-event actor replay

Run `node --import tsx scripts/headless-actor-replay.ts --run RECORDED_RUN_DIR --out NEW_ARTIFACT_DIR`. Output is restricted to a new directory inside `.artifacts/`. The CLI first runs the integrated transaction replay preflight, verifying tool/lock contracts, recorded dependency bytes, source commits and final source. Actor replay also requires the current prompt to match the recorded prompt. Node network access is disabled and mandatory Chromium checks abort external requests. There is no live-model fallback.

`src/headless/actor-replay.ts` runs the actual `SlideRuntime`, speech gates and OpenAI SDK adapters. Original provider request bodies must match byte for byte before a literal recorded response is released. The driver supplies recorded gate tick values and releases provider/tool completions in recorded event order. At durable input delivery it first verifies the actual semantic speech snapshot, then supplies its recorded monotonic clock value to the gate. No source, factual input, revision or arbitrary model context is ignored.

Generation tools execute against the actual canonical backend and mandatory checks. `RecordedTools` projects historical snapshot and transaction handles only after checking actual source, scope, every line/hash, revision and complete tool result. Returned source snapshots are verified too. Accepted mutation execution occurs at its authoritative recorded commit event; its return remains held until the recorded tool completion. This allows the actual scheduler to react to publication and later input in the recorded order. Every actual commit and lifecycle/generation tool result is checked at the end.

This is virtual event replay, not a new latency measurement or a rerun of browser validation at its original wall-clock concurrency. Browser work is serialized at recorded commit points. Supported coverage is Fast/Slow, overlapping speech decisions, durable input, explicit slide creation, successful provider responses and non-image generation tools. Specialist/task identities, user pause/history controls, explicit screenshots, duplicate/coalesced gate receipts and transport failures are not qualified; unsupported traces or changed contexts refuse. No general actor-replay qualification is inferred from a successful supported trace.

The synthetic integration test records the real actor/gate/SDK path with an explicitly synthetic HTTP transport, replays with real Chromium, and verifies that changed initial context, changed source-read hashes and unsupported controls fail closed. It makes no paid calls.

The real-model pilot recording at `.artifacts/runs/headless-integration-2026-10-31/pilot-01` replayed successfully into `pilot-01-actor-replay/`: all 26 literal provider requests, 12 tool results and six canonical commits matched. Five source snapshot handles and two transaction UUIDs were verified and mapped. Final source SHA-256 remained `35a6018667fb0162a1dec61a33c1ab3ea9d2973cb548cf1c7caad4d2541010de`, and mandatory final readiness passed. `report.json` and `transaction-preflight/report.json` retain the evidence and coverage limits. This pilot is not the five-talk qualification or a responsiveness comparison against the frozen baseline.
